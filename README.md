# Alabama Mental Health Systems Report — draft for review

A public, searchable, interactive edition of the *Alabama Mental Health Systems Report* by **Little Orange Fish** (Huntsville, Alabama): the October 2026 draft (v261003.1) after every claim in it was checked against its cited source. Generated by the Manuscript Interrogator (builder 0.5.2) from `content-pack/`, `mode: topic`.

The site has five jobs: **read the report** with the source of every sentence one hover away; **see what the check changed** (744 logged changes, 95 open items); **explore Alabama on a map** (67 counties, the Department of Mental Health's own service areas); **explore the system as a graph** (the report's 12 parts and the links of its dependency table); **compare Alabama with the other states**.

## This is a draft for review

- The report has **not been approved** by Little Orange Fish and is not a position of the North Alabama Mental Health Coalition or any of its members. It contains no clinical guidance. It is **not peer reviewed**.
- Every change the check made is **pending the author's decision** (`/changes`); what the check could not settle is on `/open-items`.
- A banner on every route says so and cannot be dismissed. `manifest.venue` is on `/` and `/about`; the `as_of` date (3 October 2026) is on `/`, `/read`, `/about`, both maps and `/systems`.
- Errors: open an issue with the **Report an error** template (page or block id, what is wrong, the source that shows it).

## Quick start

Double-click **`App Shortcuts/▶ Open Alabama Mental Health Explorer.command`** (made by the Cowork project). It installs on first run, rebuilds when something changed, and opens **http://localhost:4187/**.

By hand:

```bash
npm ci
npm run build:content      # validate content-pack/, emit src/data/*.json + public/provenance.json
npm run build              # tsc + vite → dist/ (BASE_PATH=/repo/ for GitHub Pages)
npm run preview -- --port 4187 --strictPort
npm test                   # Vitest
npm run test:e2e           # Playwright against dist/ on :4173 (BX_PORT=… if that port is taken)
```

## Editing the content pack

`content-pack/` is the only source of content. The loop:

1. Edit a pack file (`review.md`, `claims-ledger.yaml`, `changes.yaml`, `open-items.yaml`, `references.yaml`, `glossary.yaml`, `concepts/*.md`, `geo/*`, `systems/indicators.json`, `figures/data/*`).
2. `npm run build:content`. It validates every file (zod schemas in `scripts/lib/schemas.ts`), parses `review.md` into blocks, links citations and glossary terms, anchors every ledger claim, indexes changes and open items, builds the maps and the graph, builds the search index, and prints a summary table. Any error is listed, written to `content-pack/BUILD-ERRORS.md`, shown on `/methods`, and the command exits non-zero — whatever validated is still emitted.
3. `npm run build && npm run preview`, check, commit `content-pack/` and `src/data/` together.

**Known pack errors.** The pack as delivered has 12 errors the builder may not repair (listed in `content-pack/BUILD-ERRORS.md` and on `/methods`): one ledger quote that matches twice in its block (B0100.f), nine changes and two open items pointing at blocks that are not in the text (headings and removed passages). CI runs `npm run build:content -- --accept-known`, which still lists every error but exits 0 only when each is already recorded in the committed `BUILD-ERRORS.md`: any new error fails the deploy, and fixing one updates the file.

### Rules the build enforces

- **Uncited prose fails** (APP-SPEC §6.1): any block of 25+ words with no `[n]` and no `<!-- framing -->`.
- **Block ids**: every paragraph and list item ends `<!-- b: B0123 -->` (markers before it); a table has its id on the line above. Ids become anchors (`/read#b-B0123`; `+` is written `-`).
- **Claim anchors** (KICKOFF §4b): a ledger `quote` must match exactly once in its block's rendered text after normalising emphasis, comments, `<br>` and whitespace. Zero or several matches is a build error, never re-pointed. Beyond §4b the pack also uses: table-row quotes written with a bare `|` (the markdown row form) as well as ` | `; ` | ` inside a *paragraph* quote to list discontinuous fragments of one sentence (each fragment must match once, and each is underlined); and list-item quotes that begin with the markdown list marker (`1. `, `- `), which is dropped before matching.
- **Maps** (KICKOFF §4d): every CSV column has a layer and every layer a column; every FIPS has geometry; empty cells are missing values, never zero.
- **Systems graph**: node, edge, indicator and layer ids must resolve.

## How it is built

- Vite + React 18 + TypeScript (strict) + Tailwind 3; react-router 6; Recharts for the charts; `us-atlas` geometry projected **at build time** into SVG paths (`scripts/lib/geo.ts`), so the browser ships no projection code and fetches nothing; MiniSearch for search; `diff` for the change log; Carlito self-hosted via `@fontsource/carlito`.
- The reader's text is compact hast built at content-build time (`scripts/lib/review.ts`): citations, terms and claims are matched on **rendered text**, so `_Hunter_ consent decree` matches the glossary variant "Hunter consent decree" with the italics kept inside the link. One delegated popover layer (`src/components/HoverLayer.tsx`, loaded on first interaction) serves every citation, term and claim on the site.
- The notepad is ported from `ptsd-inflammation-critique` at `afb9dab` (APP-SPEC §3.1): localStorage keyed by `alabama-mental-health-systems`, and under `npm run dev`/`preview` on localhost an autosave to `notes/notepad.md` and `notes/notepad.json`. Anywhere else (GitHub Pages) it says "Saved in this browser only — export to keep a copy."
- Performance: the report data is split in two chunks, and a small build plugin (`vite.config.ts`, `routePreload`) preloads the current route's page and data chunks from `index.html`. Lighthouse (mobile, simulated throttling, local preview, 4 Oct 2026): `/read` performance 90 / accessibility 100; `/map/alabama` 93 / 100; `/systems` 93 / 100.

## Brand and contrast

Little Orange Fish's colours and type (`content-pack/brand/brand.yaml`) replace the design system's accent, neutrals and fonts. Measured WCAG 2.1 contrast:

| Use | Colour | On | Ratio |
|---|---|---|---|
| Body text | `#222222` | white | 15.9:1 |
| Soft text | `#555555` | white | 7.5:1 |
| **Links and small orange text** | **`#a84f17`** (a darker shade of the brand orange) | white / `#f3f3f3` / `#fbe5d6` | **5.5 / 5.0 / 4.6:1** |
| Section headings (bold, ≥ 18 px) | `#e47229` | white | 3.1:1 |
| Dark theme text / links / headings | `#e8e6e3` / `#f0a46b` / `#e8762b` | `#1b1d1f` | 13.6 / 8.2 / 5.7:1 |

`#e8762b` itself measures **2.98:1** on white, just under the 3:1 that large text needs, so headings use `#e47229` (the same hue, barely darker) and `#e8762b` is kept for rules, fills, the Alabama outline on the US map and the theme colour. The logo is used as supplied (on a white rounded panel in dark mode); the favicon is the fish mark cropped from the left 46% of the supplied image.

## Provenance

- Every sentence, definition, summary, number and label comes from `content-pack/`. Gaps render as amber `TODO(author)` markers and list on `/methods`.
- The report's text is rendered as written. Passages marked `<!-- synthesis -->` (97) carry the label **analysis**; `<!-- framing -->` passages (88) carry no claim of fact.
- The maps show values as published. The only computations are the five-class quantile breaks (d3 `scaleQuantile`) and an area's position in the ordered list ("12th highest of 67"), each labelled "computed from the published values".
- The 988 call centers are given in `overlays.json` with a city only; their map marker's county is taken from the crisis-center record in the same file for the same city, and the legend says so. All facility markers sit at their county's centroid, not at a street address.
- `public/provenance.json` holds the build's counts.
